JS 한 파일로 사용하는 동기화 라이브러리개발 중인 검증 예제

rollback-netcode

서로 다른 컴퓨터가 같은 게임을 계산하는 상황을 확인하는 예제예요. 처음에는 기본 설정에서 시작을 누르고, 아래 두 줄의 점과 점수가 함께 맞춰지는지 보세요.

준비됐어요. 기본 설정은 이 화면 안의 두 컴퓨터를 실제 WebRTC로 연결해요.

처음이면 이 순서로 확인하세요

  1. 시작 → 점 움직이기. 플레이어 A의 화살표를 잠깐 누른 뒤 놓으세요. 위·아래 줄은 각각 컴퓨터 A와 B의 계산 결과예요. 입력을 놓은 뒤 두 줄의 점 위치가 같아지면 정상이에요.
  2. A 점수 명령 → 점수 비교. 버튼을 한 번 누르세요. 컴퓨터 A와 B의 카드에서 플레이어 A 점수가 같은 값으로 올라가는지 보세요. 한 번의 명령이 양쪽에 전달되는 검증이에요.
  3. 리플레이 확인 → 결과 일치. 움직임을 멈추고 누르세요. 저장한 입력을 처음부터 다시 계산해 “리플레이 결과 일치”가 나오면 재현에 성공한 거예요.
  4. 복구도 보려면 개발자 상세를 여세요. 상태를 고의로 어긋내기를 누른 뒤, 컴퓨터 B의 상태 복구 횟수가 늘고 두 줄이 다시 맞는지 확인하세요.

기본 검증은 한 브라우저에 참가자 두 개를 만들고 실제 WebRTC로 통신해요. 별도 기기 두 대로 보려면 방 만들기·방 참가를 선택하세요. 기본 편도 지연은 80ms예요. 움직이는 동안 두 줄이 잠깐 다르거나 롤백 횟수가 늘어나는 것은 입력 예측을 고치는 정상 동작이에요.

두 컴퓨터가 계산한 같은 게임

● 초록 점: 플레이어 A● 파란 점: 플레이어 B
각 컴퓨터가 계산한 위치는 아래 개발자 상세에서도 확인할 수 있어요.
플레이어 A (← → 키)멈춤
플레이어 B (A D 키)멈춤

화살표를 누르고 있으면 움직이고, 놓으면 멈춰요. 다른 창으로 이동해도 입력을 해제해요. 점수 명령은 같은 난수 기준으로 계산한 1~9점을 한 번 더해요.

컴퓨터별 동기화 수치

먼저 플레이어 A·B 점수가 두 카드에서 같은지 보세요. 롤백 횟수는 늦은 입력을 고친 횟수, 상태 복구는 실제 불일치를 복구한 횟수예요.

진행 틱(계산 단계)이 다르거나 입력을 예측 중이면 현재 상태 해시가 달라도 정상이에요. 라이브러리는 확정된 같은 입력 이력의 해시를 비교해서 오류를 판단해요.

개발자 상세 · 고의 오류와 복구 확인

이 예제는 게임 상태를 32바이트 정수 데이터로 저장해요. 틱 하나의 계산 시간은 고정돼 있어요. 기본 검증은 이 페이지 안의 실제 WebRTC 연결 두 개를 사용하고, 방 연결에서는 Nostr가 상대 찾기와 연결 정보 전달만 담당해요.

고의 오류 버튼은 컴퓨터 B의 상태를 바꿔요. 확정 입력의 불일치를 감지하면 검증한 과거 상태에서 다시 계산해 복구해요. 상태 복구 횟수 증가와 두 줄의 위치 일치를 보세요. 별도 기기로 테스트할 때는 B를 조작하는 기기에서 눌러 주세요.

편도 지연은 시작 전에 선택하고, 새 입력 지연은 연결 후 적용해요. 아래 JSON과 오류 원문은 개발자가 원인을 확인하는 기술 정보예요. 이 화면은 라이브러리 검증용이며 완성된 게임은 아니에요.

아직 시작하지 않았어요.
